## Summary

Enhance the existing reports screen with comprehensive financial analytics including spending trends, income vs expense balance, budget performance tracking, enhanced installment analytics, wallet distribution, and transaction source analysis. The implementation extends the current two-tab structure (expenses, installments) by adding new sections and visualizations within each tab using existing chart widgets and UI patterns.

## Key Implementation Details

### Data Flow

1. **Reports Screen** watches `reportsDataProvider` (new composite provider)
2. **reportsDataProvider** aggregates:
   - `monthlyTransactionsProvider` (existing)
   - `multiMonthTransactionsProvider` (new - 6 months of data)
   - `activeBudgetsProvider` (existing)
   - `walletsProvider` (existing)
   - `activePlansProvider` (existing)
3. **Calculation functions** in `report_calculations.dart` process raw data
4. **Widget components** receive calculated data and render visualizations

### New Providers Needed

| Provider | Purpose | Returns |
|----------|---------|---------|
| `multiMonthTransactionsProvider` | Last 6 months of transactions | `List<Transaction>` |
| `monthlyTotalsProvider` | Income/expense totals by month | `Map<String, (income, expense)>` |
| `budgetPerformanceProvider` | Budget vs actual spending | `List<BudgetPerformance>` |
| `walletDistributionProvider` | Wallet balances with percentages | `List<WalletBalance>` |
| `sourceBreakdownProvider` | Transactions by source | `Map<String, (count, amount)>` |
| `upcomingPaymentsProvider` | Next 3 months installment payments | `List<UpcomingPayment>` |

### New Repository Methods

| Method | Location | Purpose |
|--------|----------|---------|
| `getByMonthRange(startMonth, endMonth)` | `transaction_repo.dart` | Fetch multi-month data |
| `getUpcomingPayments(months)` | `installment_service.dart` | Next N months payments |
| `getProjectedPayoffDate()` | `installment_service.dart` | When all installments complete |
